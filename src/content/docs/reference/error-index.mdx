When AnyPS5 encounters an unsupported feature, illegal instruction, or invalid container format, it prints an exact message to standard error and throws `std::runtime_error`. This page indexes 2,057 distinct error messages extracted across `core/`.

## Error handling architecture

AnyPS5 follows a strict fail-fast policy:

1. **No silent corruption**: The runtime never returns fabricated data or dummy pointers for unimplemented system state.
2. **Explicit messages**: Functions report their component name and failure cause (such as missing relocations, invalid opcode encodings, or unmapped direct memory ranges).
3. **Process termination**: The process aborts immediately, allowing developers to inspect call stacks with a debugger or examine core dumps.

## Resolving errors

When troubleshooting an error message:

1. Match the error string against the [troubleshooting guide](/AnyWiki/user-guide/troubleshooting/) for common root causes and fixes.
2. Check the relevant subsystem technical debt file in `docs/dev/debt/` in the upstream repository to verify whether the behavior is a known limitation.
3. If an export is unimplemented (`NotImplemented_nid_no_patch`), consult the [library model specification](/AnyWiki/reference/library-model/) and consider contributing an implementation following the [contributor workflow](/AnyWiki/contributing/workflow/).
