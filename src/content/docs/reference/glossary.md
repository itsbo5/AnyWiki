This glossary defines technical terms, binary formats, and architectural components referenced throughout the AnyPS5 documentation.

## Binary formats and execution

### ELF (Executable and Linkable Format)

The standard open file format for executable binaries, object code, and shared libraries across Unix-like systems. Unencrypted PlayStation 5 applications and converted Linux binaries are 64-bit ELF images (`ELF64`).

### SELF (Signed ELF)

Sony's proprietary container format wrapping PlayStation executable binaries. SELF containers embed digital signatures, encryption metadata, and compression chunks. SELF files (such as `eboot.bin` or game `.prx` files) must be unwrapped into plain ELF files before relinking.

### PRX (PlayStation Relocatable Executable)

The dynamic shared library format used on PlayStation operating systems. In AnyPS5, system PRX modules are reimplemented as native host dynamic libraries (ELF shared objects on Linux, PE dynamic link libraries on Windows) installed in `libs/*.prx`.

### SCE module

A dynamic library shipped directly by a game title within its own `sce_module/` directory. SCE modules contain engine subsystems, middleware (such as audio rendering or UI libraries), and helper utilities. The relinker converts these bundled modules directly rather than replacing them with host implementations.

## Linking and symbol resolution

### NID (Numeric Identifier)

An 11-character alphanumeric identifier used to reference exported functions and global variables across PlayStation modules. NIDs are generated by computing a SHA-1 digest of the symbol name concatenated with a 16-byte cryptographic salt, followed by byte reversal and URL-safe Base64 encoding.

### PLT (Procedure Linkage Table)

A table of trampoline code stubs generated in executable binaries. When application code invokes an external dynamic library function, it jumps to a PLT stub, which reads the destination address from the Global Offset Table.

### GOT (Global Offset Table)

A table of absolute memory addresses populated by the dynamic linker at runtime. The GOT decouples position-independent code from the physical memory locations of external library symbols.

### VABI (`APS5_VABI`)

The calling convention bridging macro defined in `core/libs/prx`. On Windows, `APS5_VABI` expands to `__attribute__((sysv_abi))`, directing the compiler to emit System V AMD64 register calling sequences for exported functions called by the converted binary. On Linux, the macro expands to nothing because System V ABI is native.

### Silent stub (inert function)

A function implementation in a PRX library that returns success (such as `0` or `SCE_OK`) without executing real system actions. Silent stubs are permitted only for non-essential user interface features or telemetry reporting, and must be documented in `docs/dev/debt/`.

## Graphics and hardware

### RDNA2

The AMD Radeon GPU microarchitecture implemented in PlayStation 5 silicon. The AnyPS5 shader recompiler translates 1,166 documented RDNA2 machine instruction opcodes into standard SPIR-V bytecode.

### SPIR-V (Standard Portable Intermediate Representation)

A standardized intermediate bytecode representation for compute and graphics shaders defined by the Khronos Group. The AnyPS5 shader recompiler targets SPIR-V 1.3 and 1.5 for consumption by host Vulkan graphics drivers.

### udmabuf (User DMA Buffer)

A Linux kernel driver facility that creates DMA-buf file descriptors from anonymous user memory allocations. AnyPS5 uses udmabuf on Linux to achieve zero-copy memory sharing between host CPU buffers and GPU devices.

### DWARF / `.eh_frame`

Standardized debugging and exception handling unwind tables embedded in ELF binaries. The relinker uses `.eh_frame` and `.eh_frame_hdr` sections to determine precise function boundaries when scanning code interleaved with static data.
